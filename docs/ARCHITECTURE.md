# 架構說明

## 核心概念：內容與版型分開

| 層 | 放什麼 | 誰會改 |
|---|---|---|
| 區塊庫 | 區塊的 HTML 結構、CSS 樣式、互動邏輯、欄位規格 | 設計規範變動時才改，改一次全部專案受惠 |
| 內容資料檔 | 每個專案的文案、圖片路徑、選用的變體 | 每個專案各一份，日常最常改 |
| 組裝腳本 | 讀內容資料檔、套用區塊與品牌樣式，輸出可直接開啟的頁面 | 很少改 |

## 分層：core 與 brands

- `core/`：PF.com 與 YCO **都原樣使用**的區塊與規則。
- `brands/pfcom/`、`brands/yco/`：品牌專屬的樣式變數（色彩、字級、間距）、素材（icon、把手圖）、必要時的區塊覆寫。
- PF.com 的 2B 以 2C 為基礎，只放差異。
- 搬進 `core/` 的條件：兩個品牌都不改就能用。只有一個品牌用的，留在該品牌下。

## 欄位規格（schema）是表單頁的基礎

每個區塊有一份 `block.schema.json`，定義：有哪些欄位、型別、是否必填、預設值、給人看的標題與說明。

同一份規格同時用來：

1. 驗證內容資料檔有沒有缺欄位或填錯。
2. 之後自動產生表單頁的輸入欄位（文字框、圖片上傳、下拉選單），不必每個區塊另外手刻表單。

所以現在花時間把規格寫好，是為了後面的表單頁。

## 階段

| 階段 | 內容 | 狀態 |
|---|---|---|
| Phase 0 | 建立 GitHub repo、資料夾骨架、命名規則 | 進行中 |
| Phase 1 | Topbanner 試做：欄位規格、區塊樣式、組裝腳本、自動驗證 | 下一步 |
| Phase 2 | 擴充其餘區塊；PF.com 2C 的 Topbanner 驗證 core/brands 切分是否合理 | 待定 |
| Phase 3 | 表單頁：依規格產生欄位、圖片上傳、一鍵產出 | 待定 |
| Phase 4 | 多人使用：部署位置、權限、素材儲存 | 待定 |

## 已知待決定的事項

- 表單頁要跑在哪裡（個人電腦本機、公司內部伺服器、或雲端），決定多人使用的方式。Phase 3 之前決定即可。
- 大型素材（影片、高解析圖片）放哪裡：直接放 repo、Git LFS、或獨立儲存空間。Phase 1 先用小素材試，觀察大小再決定。
- Topbanner 試做的驗收標準（尺寸、字級、互動是否與現有 YCO 頁面一致）。
