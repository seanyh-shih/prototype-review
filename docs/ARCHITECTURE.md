# 架構說明

## 核心概念：內容與版型分開

| 層 | 放什麼 | 誰會改 |
|---|---|---|
| 區塊庫 | 區塊的 HTML 結構、CSS 樣式、互動邏輯、欄位規格 | 設計規範變動時才改，改一次全部專案受惠 |
| 內容資料檔 | 每個專案的文案、圖片路徑、選用的變體 | 每個專案各一份，日常最常改 |
| 組裝腳本 | 讀內容資料檔、套用區塊與品牌樣式，輸出可直接開啟的頁面 | 很少改 |

## 分層：core 與 brands

- `core/`：PF.com 與 YCO **都原樣使用**的區塊與規則。
- `brands/pfcom/`、`brands/yco/`：品牌專屬的樣式變數（色彩、字級、間距）、素材（icon、把手圖）、必要時的區塊覆寫。
- PF.com 的 2B 以 2C 為基礎，只放差異。
- 搬進 `core/` 的條件：兩個品牌都不改就能用。只有一個品牌用的，留在該品牌下。

## 欄位規格（schema）是表單頁的基礎

每個區塊有一份 `block.schema.json`，定義：有哪些欄位、型別、是否必填、預設值、給人看的標題與說明。

同一份規格同時用來：

1. 驗證內容資料檔有沒有缺欄位或填錯。
2. 之後自動產生表單頁的輸入欄位（文字框、圖片上傳、下拉選單），不必每個區塊另外手刻表單。

所以現在花時間把規格寫好，是為了後面的表單頁。

## 專案設定：執行前必須先確定品牌

每個專案開始之前，必須先確定這次做的是 **YCO** 還是 **PF.com**。品牌決定了用哪一套樣式變數、素材、可用的區塊，以及輸出位置，選錯會整頁出錯。

```yaml
project: api-ai-hair-extension   # 專案名稱（kebab-case）
brand: yco                       # 必填：yco｜pfcom。沒有預設值
segment: 2c                      # 只有 brand 為 pfcom 時必填：2c｜2b
```

規則：

1. `brand` **必填且沒有預設值**。沒填、或填了不認得的值，組裝腳本直接停下並說明原因，不會「猜一個」繼續做。
2. 表單頁的**第一步就是選品牌**（選了 PF.com 才會再出現 2C／2B）。選完之前，其他欄位都不開放填寫。
3. 品牌連動：樣式變數與素材取自 `brands/<brand>/`；區塊若沒有該品牌可用的版本，驗證時明確報錯，不會悄悄套用別的品牌的樣式。
4. 輸出位置帶品牌，延續舊流程慣例，例如 `outputs/yco/<專案名>/`、`outputs/pfcom/<segment>/<專案名>/`。
5. 專案建立後不建議更改品牌。要換品牌請另建新專案，再從舊專案複製內容。

## 區塊的多版本比較（單一選擇／複數選擇）

內部評估不同版本時，同一個區塊可以放 2～3 個候選，頁面上出現切換按鈕。這取代舊流程的 A/B Toggle（做法記錄在舊文件 DESIGN-RULES §5.11）。

### 名詞

| 名稱 | 意思 |
|---|---|
| 單一選擇（預設） | 區塊只有一個版本，產出正式頁面，沒有切換按鈕 |
| 複數選擇 | 區塊有 2～3 個候選版本，產出的頁面有 A/B（或 A/B/C）切換按鈕，供內部評估 |
| 候選代號 | `a`、`b`、`c`（頁面上顯示 A、B、C），取代 V1/V2/V3。每個候選另有中文名稱（`label`）方便辨認 |

### 表單頁行為（規劃）

1. 每個支援多版本的區塊有一個下拉選單：**單一選擇／複數選擇**，預設單一選擇。
2. 選「複數選擇」時，下方內容區多出第二張候選卡片。每張候選卡片都有自己的標題、內文、**格式下拉選單**（一般格式〔影片＋圖片〕、Before/After、Slider），以及該格式對應的上傳欄位。「一般格式」固定為影片加圖片成對上傳。每個格式的素材清單見各區塊自己的 README（例如 `core/blocks/topbanner/README.md`）。
3. 卡片下方有「＋」可新增候選，最多 3 個，滿 3 個時不再顯示。
4. 從複數切回單一時，詢問要採用哪一個候選；其他候選的內容保留、不刪除，之後可以切回複數再用。
5. 只要頁面中有任何區塊是複數選擇，整頁顯示狀態提示（例如「評審版：含 1 個比較區塊」），避免誤把含切換按鈕的頁面當成正式版交出。

### 專案檔格式

```yaml
- id: topbanner
  mode: multiple            # single（預設）｜multiple
  use: b                    # 只有 single 模式使用：採用哪一個候選
  options:                  # 候選內容，最多 a、b、c 三個；各自是一份完整的區塊內容
    a:
      label: "影片版"
      variant: standard
      # ...標題、內文、媒體等，格式同 block.schema.json
    b:
      label: "拖曳比較版"
      variant: before-after
      # ...
```

- `mode: single` 時只輸出 `use` 指定的那個候選，沒有切換按鈕。
- `mode: multiple` 時輸出全部候選，按鈕順序為 a、b、c，預設顯示 a。
- 沒有多版本需求的區塊，不需要寫 `mode` 和 `options`，直接寫一份內容即可。

### 切換按鈕樣式

2 個版本（A/B）的樣式沿用舊流程。3 個版本（A/B/C）的樣式待設計提供後再實作。

## 階段

| 階段 | 內容 | 狀態 |
|---|---|---|
| Phase 0 | 建立 GitHub repo、資料夾骨架、命名規則 | 完成 |
| Phase 1 | Topbanner 試做：欄位規格、區塊樣式、組裝腳本、自動驗證 | 進行中：規範與樣式已搬入、最小組裝腳本完成並與現有 YCO 頁面比對一致；待補：自動化測試、Slider |
| Phase 1b | Topbanner 的多版本比較（單一選擇／複數選擇）：組裝腳本支援 `mode`／`options`，評審版切換按鈕 | Phase 1 之後 |
| Phase 2 | 先以 YCO 為主，擴充其餘區塊 | 待定 |
| Phase 2b | 用同樣方式建立 PF.com：先做 2C 的 Topbanner，驗證 core/brands 切分是否合理 | YCO 確定後 |
| Phase 3 | 表單頁：依規格產生欄位、圖片上傳、一鍵產出 | 待定 |
| Phase 4 | 多人使用：部署位置、權限、素材儲存 | 待定 |

## 已知待決定的事項

- 表單頁要跑在哪裡（個人電腦本機、公司內部伺服器、或雲端），決定多人使用的方式。Phase 3 之前決定即可。
- 大型素材（影片、高解析圖片）放哪裡：直接放 repo、Git LFS、或獨立儲存空間。Phase 1 先用小素材試，觀察大小再決定。
- Topbanner 試做的驗收標準（尺寸、字級、互動是否與現有 YCO 頁面一致）。
